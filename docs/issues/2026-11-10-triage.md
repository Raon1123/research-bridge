## 3. Work that exists only in documents: proposed new issues

Each entry: title; body (three to six lines); labels (only labels that exist in the repository); design document.

**N-01. design: resend failed messages from the outbox**
Body: `send_message` returns `pending_send` when the node is unreachable, and the hub keeps a masked copy under `outbox/<node>/<msg_id>/`. Nothing resends it; `rb sync` does not. A retry design must settle: the stored copy is masked (not the sent text when lines were blanked), attachment files are not copied, the node compares only attachments on a retry, and messages a session already resent by hand. Related: #15, #16; decision list item 8.
Labels: `design`, `host`. Design: `docs/design/2026-11-10-sync-and-hub-page.md` §6.9.

**N-02. design: record session-to-session messages on one machine**
Body: the bridge records only node traffic. Messages between two Claude sessions on the hub are not visible on the hub page. Recording them needs a Claude Code hook on the message tool (a change to the user's settings) or reading transcripts (private, outside the masking rules). Decide whether it is wanted, then design.
Labels: `design`, `host`. Design: `docs/design/2026-11-10-sync-and-hub-page.md` §6.9.

**N-03. hub: reuse one SSH connection per pass (ControlMaster)**
Body: one `rb sync` pass opens one connection for `hello`, `poll` and `git_status`, and the board sources open their own. OpenSSH connection sharing (`ControlMaster`) would cut connections and agent prompts. Needs a decision on the socket directory and lifetime, and a check that a shared master cannot outlive a revoked key.
Labels: `enhancement`, `host`. Design: deferred in `docs/design/2026-11-10-setup-and-diagnosis.md` §3 and `docs/design/2026-11-10-sync-and-hub-page.md` §3.

**N-04. node: mailbox size limit**
Body: the node mailbox (`in/`, `out/`, `state/`) has no total size limit; each attachment is capped at 50 MB, but the number of messages is not. Define a quota, what happens when it is reached (refuse new messages with a code), and how `rb-node doctor` reports usage.
Labels: `enhancement`, `node`. Design: none yet (deferred in the 2026-11-10 review; write one from `docs/design/TEMPLATE.md`).

**N-05. design: approval form on the hub page**
Body: approval is `rb approve` in a hub terminal or the loopback `/rb/approve` route on the laptop's 8765. A form on the hub page (port 8767) would be a third surface and changes the text of hard rule 1. It would also need a cross-site request forgery token, a passphrase field and an `Origin` check on a page that holds message bodies. Only after the user decides (decision list item 3).
Labels: `design`, `security`, `host`. Design: `docs/design/2026-11-10-sync-and-hub-page.md` §6.9.

**N-06. hub: return the SSH error code separately from the hint in MCP results**
Body: MCP tool results return `{"error": str(exc)}`; for a classified SSH error the string carries the code's message and the next command in one text. A session cannot branch on the code without parsing text. Add `code` and `hint` fields next to `error` (additive; old fields unchanged), with a test per tool.
Labels: `enhancement`, `host`. Design: `docs/design/2026-11-10-setup-and-diagnosis.md` §6.4 and §12 (the call "str(TransportError) carries the hint").

**Already tracked: to_session, reply_to, responder arbitration, host-key pinning**
These deferred items already have issues: `to_session` → #15, `reply_to` to the node → #16, responder arbitration with a live session → #41, host-key pinning in code and request authentication → #25. Proposed action: the rewrites in section 1, no new issue.

**N-10. security: SEC-05 config loader and SEC-06 pdftotext exposure (split from #26)**
Body: SEC-05: the session-chosen config goes to the fixed `job_template`; whether that is code execution depends on the project's config loader (confirm data-only loading; show content or hash at approval, partly done: `rb approve` shows path and sha256). Labels: `security`, `node`, `host`, `sev:S2`. Design: issue 26 table; SEC-05 also `docs/design/2026-11-10-experiment-records.md` §7.

**N-11. design: hub attachment root for send_message**
Body: `send_message` accepts any hub file path as an attachment (`rb_host/server.py`), so a session can send any file the hub user can read, up to 50 MB. Design an allowlisted attachment directory (or a per-call confirmation), keep the 50 MB cap, and test that paths outside it are refused.
Labels: `design`, `security`, `host`. Design: `2026-11-03-whole-branch-review.md` PM-13.

**N-12. node: build each get_file transfer once**
Body: each `get_file` call reads, masks and hashes the whole file and returns one 1 MiB slice; a 50 MB file is read 50 times, and a change between calls breaks the final hash. Build the outgoing bytes once into a node-side spool file per (path, mtime) and serve slices from it; add a test that counts reads for a three-chunk transfer.
Labels: `enhancement`, `node`, `sev:S2`. Design: `2026-11-03-whole-branch-review.md` PM-15.

**N-13. hub: board fetch helper separate from fetch_file**
Body: `rb_host/board.py` calls `server.fetch_file`, which writes to `fetched/<node>/<basename>` and then deletes the copy, so a file a session fetched under the same name is overwritten and deleted; `server.*` also reloads `host.json`. Add a board-private fetch helper that takes `cfg` and writes under `board/tmp/`.
Labels: `defect`, `host`, `board`, `sev:S2`. Design: `2026-11-03-whole-branch-review.md` PM-16.

**N-14. decision: self-approval residual**
Body: `rb approve` needs a real terminal and the approval passphrase, and the node checks the key derived from it. A session that can open a pseudo-terminal and knows the passphrase can still approve. Accept this residual in writing, or design a control the session cannot reach (for example confirmation on a second device).
Labels: `security`, `host`, `user-action`. Design: `2026-11-03-whole-branch-review.md` PM-04.

**N-15. node: confine the responder's Read, Grep and Glob to the read roots**
Body: the spawned responder runs with `--tools Read,Grep,Glob` in the research root; nothing limits those tools to `read_roots` (the reply is still masked when the hub polls it). Options: run the responder in a directory holding only the read roots, or a settings file with path rules; test with a file outside the roots.
Labels: `security`, `node`, `design`. Design: `2026-11-03-whole-branch-review.md` PM-02; hard rule 8 in `AGENTS.md`.

**N-16. laptop 8765: deploy the PR 35 vault-export files (only if the dashboard stays in use)**

Labels: `dashboard`, `security`, `user-action`. Design: `2026-11-03-whole-branch-review.md` PM-03, PM-17, PM-19.
