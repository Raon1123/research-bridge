# Audit of 2026-11-11: what was fixed and what is left

A session read the whole repository on 2026-11-11 (branch `claude/audit-2026-11-11`, cut from `main` at 6b21282): every module of `rb_node/` and `rb_host/`, the tests, the scripts, and every markdown document. Ten readers each took one part and reported what is wrong, inconsistent, inefficient or no longer needed; a second reader per part tried to refute each report against the files. Of 216 reports, 11 were refuted. The rest reduce, after merging duplicates, to the fixes in §1 and the open items in §2 to §7.

A fix was applied only when the session checked it against the code or `git log`, exactly one correct change existed, and it was not the user's decision. Everything else is listed here. Line numbers are those of the branch.

Abbreviations: PR = GitHub pull request; MCP = Model Context Protocol (the tool interface of Claude sessions); B2, B3 = the security checks and the first live run in `docs/provisioning.md`; SEC-03 = the rule that ledger text is shown stripped of control characters (`rb_host/jobs.py`, `clean`).

## 1. Fixed in this change

Code (923 tests pass; 921 before, two added):

- `rb doctor` reported a `host.json` with a wrong value type as "not valid JSON"; it now says which value has the wrong type. The block that was meant to say so could not be reached and is removed (`rb_host/doctor.py`).
- `rb-node doctor` gave, for a missing harness line, a command without `--hub-key`; `scripts/node-install.sh` skips the `authorized_keys` step without it. The command now carries both keys (`rb_node/doctor.py`).
- `rb-node <command> ... --help` printed the top-level usage unless `--help` was the second word; it now prints the command's own help. The help of `rb-node doctor` named a "git exposure" check that does not exist (`rb_node/cli.py`).
- `scripts/b2-hub.sh`: a failed node lookup was not caught (`eval "$(...)" || exit 2` never sees the status), and `--help` printed the line `set -u`.
- `tests/test_demo_dashboard.py`: one test left `rb_host.jobs.connect` pointing at a deleted demo node for the tests after it.
- The test HTTP servers stopped with the default 0.5 s poll interval; with 0.01 s the suite runs in about 45 s instead of 71 s.
- The package version is read from `rb_node.__version__` (`pyproject.toml`, `dynamic`); it was 0.1.0 while the node reported 0.2.0.
- Removed, used by nothing: `service.installed_interval`, `sync._age_s`, the `msg_id` branch of `Ledger.thread`, unused imports and variables in `rb_host/`, `rb_node/jobs.py` and ten test files, two unused options of `tests/hubfake.py`.
- Comments and docstrings that called the hub "the laptop" or said the MCP tools never call `rb_host/jobs.py`.

Documents:

- Design index and status lines named two branches as the place of work merged in PRs 47, 48 and 49; the first design's status line said "draft for user approval" beside its own note that it was approved.
- `docs/design/2026-11-10-setup-and-diagnosis.md` listed a gap as open that commit 252345c closed, and gave two closing lines for `rb-node doctor`.
- References to the removed `docs/server-facts.md`; the placeholder `<LAPTOP_ETH_SUBNET>` in two rule lists; decision numbers that named the wrong decision; `docs/provisioning.md` saying its Results section is empty.
- `docs/HANDOFF.md`: lines that said nothing had run on the real node, and the hub-side checks of B3 listed as not run.
- `docs/projects/trm.md` and `docs/projects/TEMPLATE.md`: node version, pattern file, `job_template`, approval verifier, the three `job_template` placeholders.
- Manuals, English and Korean together: the stale "State on 2026-11-10" paragraph, the `--help` wording of `config check` that the code no longer has, the four terminal-only `node.json` keys, the order of question and backup for `authorized_keys`, the fields `rejected_ids`, `hub_withheld_extra` and `hub_withheld_rejected`, the lines of `rb-web.service`, the list of commands that contact the node, the `web/access.json` row, `uv sync` with `--python '>=3.10'`. The Korean node manual lacked the re-run of the pulled script in `--update`.
- `README.md` and `README.ko.md` said the demo never deletes its data directory (it does) and that the hub page only reads files (it writes `web/access.json`).
- `AGENTS.md`: `webaccess.py`, `share.py`, `share_serve.py` in the layout; `web/` and the pattern file in the hub data list; the forms of pattern file the code accepts; the one test allowed to call `monkeypatch.undo()`.
- `deploy/node.json.example` and `deploy/authorized_keys.example` notes.

Moved to `docs/99_Archive/` (index in its `README.md`): the records of the first build (`docs/history/sdd-2026-10-27/`, 29 files) and the two finished plans (`docs/superpowers/plans/`). References in living documents were updated.
