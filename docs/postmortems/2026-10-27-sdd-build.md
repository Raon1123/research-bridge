## 2. Items

### PM-01 — Withheld filter ignored `families[*].patterns`; only fallback patterns applied

- Severity: S1
- When: introduced in Task 3 (`d7f6e58`), found in controller review, fixed in fix round 1 (`c7d4767`)
- What happened: `Withheld.load()` read a JSON list or `{"patterns": [...]}` but not the `families[*].patterns` structure of the real source file, so only the five fallback patterns were applied. The design requires the union of fallback and file patterns.
- Cause (recorded): the source format was not matched by `load()` (ledger line 51).
- How it surfaced: controller review of the implementer's DONE_WITH_CONCERNS report.
- Fix: `load()` flattens `families[*].patterns`; `exp_id_patterns` and `exp_ids` are ignored; fallback stays always on.
- Fix verified: recorded — 27/27 tests pass; the real source file loads 9 patterns (5 fallback + 4 family) (ledger line 53).
- Prevention: a test that loads a fixture with the real source's structure (`test_load_family_patterns`, Task 3 report).
- Evidence: ledger line 51 「load() ignored families[*].patterns in the real withheld_patterns.json」

### PM-02 — `get_file kind=out` skipped `Withheld.check_file` for server-written files

- Severity: S1
- When: introduced in Task 5 (`571ecaf`), fixed in fix round 1 (`ae547bc`)
- What happened: files under `mailbox/out` were sent with `scan=False`, so binaries written by a server session could leave the node without the withheld check.
- Cause (recorded): `kind=out` was treated as trusted (ledger line 57).
- How it surfaced: controller review.
- Fix: `kind=out` is scanned like `kind=doc`; md/txt/csv/json are masked; pdf/tex/images go through `check_file`.
- Fix verified: recorded — 60/60 tests pass (ledger line 59).
- Prevention: <to fill: a test that every `get_file` kind passes through the withheld check>
- Evidence: ledger line 57 「get_file kind=out skipped Withheld.check_file (scan=False)」

### PM-03 — `job_finished` event body had no event name

- Severity: S2
- When: introduced in Task 6 (`4721d0a`), fixed in fix round 1 (`981789c`)
- What happened: the event body was `{"job_id","status"}`, so `poll` could not tell which event had occurred.
- Cause (recorded): no event-naming convention existed before Task 6 (ledger line 62).
- How it surfaced: controller review against the plan's review focus 3.
- Fix: every event body carries an `"event"` key; Task 7 uses the same convention for `responder_failed`. Now `AGENTS.md` hard rule 7.
- Fix verified: recorded — 81/81 tests pass (ledger line 65).
- Prevention: hard rule 7.
- Evidence: ledger line 62 「poll cannot tell which event occurred」

### PM-04 — `rb_node/cli.py` at `4721d0a` had a SyntaxError that no test imported

- Severity: S2
- When: introduced in Task 6 (`4721d0a`), found during the PM-03 fix round, fixed in `981789c`
- What happened: escaped `\n` sequences had become real newlines in `cli.py`; the module did not parse. The suite passed because no test imported it.
- Cause (recorded): the escape change is recorded (ledger line 65); how it was introduced is not.
- How it surfaced: the fix round added a test for the `rb-node run-job` CLI, which imported the module.
- Fix: corrected in `981789c`, with the new CLI test.
- Fix verified: recorded — the new CLI test passes as part of 81/81 (ledger line 65).
- Prevention: <to fill: a test that imports every module, or that runs each CLI entry point with `--help`>
- Evidence: ledger line 65 「the original 4721d0a cli.py had a SyntaxError」

### PM-05 — Responder lock stale threshold equalled the responder timeout

- Severity: S2
- When: introduced in Task 7 (`410b59f`), fixed in fix round 1 (`e680803`)
- What happened: `LOCK_STALE == RESPONDER_TIMEOUT` (1800 s), so a responder still running at its full timeout could lose its lock to a second responder, breaking "one at a time" (hard rule 8).
- Cause (recorded): both constants were set to the same value (ledger line 67).
- How it surfaced: controller review.
- Fix: `_lock_stale()` returns `RESPONDER_TIMEOUT + 300`, evaluated at call time; a test pins the invariant.
- Fix verified: recorded — 96/96 tests pass (ledger line 69).
- Prevention: the invariant test.
- Evidence: ledger line 67 「a run at its full timeout could lose the lock to a second responder」
